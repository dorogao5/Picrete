# Вход через ITMO ID и запуск курса неорганической химии

Основной курс — `infochem-29`, ID `c797dfdc-6b78-4ffc-af30-17750a4aed77`, название «Неорганическая химия». Нельзя удалять и создавать курс заново: ID связывает участников, материалы, банк и Studio.

## Официальная интеграция

Проверено 08.09.2026:

- https://docs.itmo.id/auth-oidc/requests/ — Authorization Code, token endpoint, userinfo, JWKS.
- https://docs.itmo.id/scopes/profile/ — `sub`, необязательный `isu`, ФИО (scope `name`), email.
- https://docs.itmo.id/scopes/edu/ — scope `edu`: `groups[].name`, `groups[].course`, `is_student` (поля необязательны).
- https://id.itmo.ru/auth/realms/itmo/.well-known/openid-configuration — живой discovery подтверждает issuer, PKCE S256 и RS256.

Нужен конфиденциальный клиент OIDC с разрешениями `openid name email edu`, Authorization Code Flow, PKCE S256, подписью ID Token RS256 и точным redirect URI `https://picrete.ru/auth/itmo/callback`. Иконка: `https://picrete.ru/itmo-service-icon.svg` (SVG 1:1). Не нужны доступ ко всему контингенту, service accounts, offline access, данные паспортов, адресов или телефонов студентов.

## Включение после согласования ИТМО

В `/srv/picrete/shared/secrets/picrete.env` (root, 0600) заполнить `ITMO_ID_CLIENT_ID`, `ITMO_ID_CLIENT_SECRET`, `ITMO_ID_REDIRECT_URI`, `ITMO_ID_ALLOWED_GROUPS` (точные имена групп через запятую) и установить `ITMO_ID_ENABLED=true`. Docker Compose передаёт эти параметры только API. Пересоздать API существующим compose-проектом `app`; секреты не передавать в аргументах CLI, Git, фронтенде или сообщениях.

Пустой список групп запрещает автоматическое зачисление. Вход и создание аккаунта возможны, но курс нужно получить по приглашению преподавателя. Для зачисления одновременно необходимы `is_student=true`, `course=2` и группа из списка. Приостановленные или покинутые членства не активируются. Обычный вход и приглашения продолжают работать. Преподавательскую роль разрешают только явно заданные администратором назначения teacher_isu; административная роль через ITMO.ID не выдаётся.

До получения client ID/secret вход отключён, кнопка скрыта. Фактический вход с университетским аккаунтом можно проверить только после выдачи доступа. Основной домен входа — picrete.ru: browser binding хранится в sessionStorage этого origin. Для другого домена потребуется отдельная зарегистрированная конфигурация callback; нельзя переносить код и binding между доменами.

## Реализованный поток

1. `GET /api/v1/auth/itmo/config` — доступность провайдера.
2. `POST /api/v1/auth/itmo/start` с `{consent:true}` — одноразовый state, nonce, PKCE verifier; frontend хранит независимый browser binding в sessionStorage. Сервер хранит хэши state/binding и срок 10 минут в PostgreSQL.
3. ИТМО возвращает code в `/auth/itmo/callback`; страница немедленно очищает URL.
4. `POST /api/v1/auth/itmo/finish` с code/state/binding атомарно погашает state, обменивает code на сервере и проверяет RS256/JWKS, issuer, audience, azp, exp, iat, nonce, опциональный at_hash и совпадение sub в userinfo.
5. `external_identities` хранит связь issuer+sub с аккаунтом и необходимые поля профиля; токены ИТМО не сохраняются. JWKS кэшируются на час. Неизвестный ключ отклоняется до обновления кэша.
6. Для существующего аккаунта: войти по логину → «Мои курсы» → «Связать с ITMO.ID» (`POST /auth/itmo/link`, требует действующий токен Picrete). Автоматического объединения по почте, имени или ИСУ нет.

Данные о группах хранятся в external_identities.profile и при первом зачислении в course_memberships.identity_payload. Они обновляются в профиле при входе; фоновая выгрузка всего контингента не предусмотрена. Отсутствие группы/статуса не трактуется как разрешение. Текущие членства не отзываются автоматически при переходе на следующий курс; состав курса контролирует преподаватель.

## Проверка перед приёмом студентов

После получения доступа пройти реальный вход: новый второкурсник из разрешённой группы попадает в курс; другая группа и первый курс не зачисляются; связь существующего аккаунта сохраняет его работы; отказ от согласия/отмена входа и повторный callback не авторизуют; приостановленный участник не восстанавливается. Проверить /readyz, курс, банк, материалы и ответ ассистента. Не включать до согласования списка учебных групп.

Резервные копии перед очисткой 8 старых завершённых работ и 15 тренажёров: `/srv/release-backups/20260908-inorganic/{picrete-before.dump,studio-before.dump}`. Полное восстановление в рабочую БД затрёт последующие изменения; для выборочного восстановления сначала развернуть dump в отдельной БД и переносить только нужные старые записи. Банк после очистки: 2198 заданий, 461 полное решение; хэши заданий/изображений/участников/привязок источников проверены внутри транзакции.

## Несколько дисциплин

Регистрация ITMO.ID выполняется для платформы Picrete, включая неорганическую, аналитическую, коллоидную химию и будущие курсы. Отдельный OIDC-клиент для каждой дисциплины не требуется в реализованной схеме.

`ITMO_ID_ENROLLMENT_RULES` — JSON-массив правил `{course_slug, study_year, groups}`. Он заменяет простую настройку ITMO_ID_ALLOWED_GROUPS и позволяет зачислять пользователя в несколько существующих курсов по независимым правилам. Например, настроить реальные группы отдельно для `infochem-29`, `analythic-chem`, `colloid-chemistry`. Не копировать вымышленные группы в рабочую конфигурацию. Пустой массив `[]` отключает автоматическое зачисление для всех дисциплин. Основным выбранным курсом после ITMO-входа становится infochem-29, если у пользователя есть активное членство; иначе используется имеющийся курс.


## Основной сценарий без отдельных аккаунтов Picrete

После включения ITMO.ID публичная регистрация Picrete отключается на UI и API. Студенты и преподаватели входят через ITMO.ID и сразу получают назначенные курсы. Внутренняя запись users создаётся автоматически для хранения результатов; отдельный логин/пароль пользователю не предлагается. Технический sub приходит от провайдера по умолчанию и не является отдельным пунктом служебной записки. Служебный вход существующих администраторов сохранён в свёрнутом блоке для сопровождения и перехода.

В каждом правиле ITMO_ID_ENROLLMENT_RULES можно задать teacher_isu (массив согласованных номеров ИСУ преподавателей этого курса). Пользователь с таким подтверждённым ИСУ при входе автоматически получает преподавательское членство; предварительная регистрация в Picrete не нужна. Прочие пользователи не получают роль преподавателя. Правило группы/года по-прежнему выдаёт только студенческий доступ. Приостановленные/покинутые членства не восстанавливаются. Для перехода старых пользователей API link остаётся инструментом миграции, но не частью основного интерфейса. Существующие записи и результаты нельзя объединять по совпадению имени/почты; их перенос требует подтверждённого сопоставления.
